# 1. Introduction

Linux is capable of running hundreds or thousands of tasks at the same time.

For example, a production server may be running:

```text
Web Server
Database
Application Server
Monitoring Agent
Backup Service
SSH
Logging Service
Security Agent
Cron Jobs
Background Workers
```

All of these activities involve **processes**.

As an Application Support Engineer, you will frequently investigate questions such as:

```text
Why is the application slow?

Why is CPU usage 95%?

Why is memory usage increasing?

Is the application process running?

Which process is using port 8080?

Why did the application stop?

Which process is consuming the most CPU?

Can I safely restart this process?
```

To answer these questions, you need to understand **Linux Process and Task Management**.

---

# 2. What is a Process?

A **process** is a running instance of a program.

Simple definition:

> A process is a program that is currently executing.

For example:

```text
Java application
     ↓
Program starts
     ↓
Linux creates a process
     ↓
Process gets a PID
     ↓
CPU + Memory are allocated
```

Suppose you have:

```bash
java -jar application.jar
```

The `application.jar` is the application.

When it starts running, Linux creates a process for it.

---

# 3. Program vs Process

This distinction is very important.

| Program | Process |
|---|---|
| Static | Running |
| Stored on disk | Exists in memory |
| Not currently executing | Currently executing |
| Example: `application.jar` | Running Java application |
| Does not have a PID | Has a PID |

Example:

```text
application.jar
```

is a program.

After running:

```bash
java -jar application.jar
```

Linux creates a process.

```text
application.jar
     ↓
Running Java Application
     ↓
PID = 2456
```

---

# 4. Why Process Management is Important

Process management helps us:

- monitor applications
- identify running applications
- stop applications
- restart applications
- troubleshoot high CPU
- troubleshoot high memory
- find crashed applications
- identify resource-consuming processes
- identify processes using ports
- investigate application performance
- manage background tasks

In Application Support, process management is a daily skill.

# 7. PID

PID means:

> **Process ID**

Every running process gets a unique process ID.

Example:

```text
PID
100
101
102
103
```

Example:

```bash
ps
```

Output may look like:

```text
PID TTY          TIME CMD
2451 pts/0    00:00:00 bash
2789 pts/0    00:00:00 ps
```

Here:

```text
2451 = PID
2789 = PID
```

PID is very important because many commands require a PID.

For example:

```bash
kill 2451
```

means:

> Send a signal to process 2451.

---

# 8. PPID

PPID means:

> **Parent Process ID**

Processes can create other processes.

Example:

```text
Parent Process
      |
      +------ Child Process
      |
      +------ Child Process
```

Suppose:

```text
bash
 |
 +---- application
```

The application process may have the shell as its parent.

You can see PPID using:

```bash
ps -ef
```

Example:

```text
UID       PID   PPID  CMD
user     2500   2200  bash
user     2600   2500  java -jar app.jar
```

Here:

```text
PID  = 2600
PPID = 2500
```

So:

```text
bash
  |
  +---- Java Application
```

---

# 9. Process Ownership

Every process belongs to a user.

Example:

```text
USER       PID
root      1001
sahil     2001
appuser   3001
```

You can check process ownership with:

```bash
ps -ef
```

Example:

```text
root       1001
appuser    2001
sahil      3001
```

This is important for permissions.

For example:

```text
Application Process
        |
     appuser
        |
Application Files
```

The application may not be allowed to access files belonging to another user.

This connects directly with:

- users
- groups
- permissions
- ownership

# 10. Process States

Linux processes can have different states.

Common states include:

| State | Meaning |
|---|---|
| R | Running |
| S | Sleeping |
| D | Uninterruptible sleep |
| T | Stopped |
| Z | Zombie |
| I | Idle kernel thread |

---

## R — Running

The process is currently running or ready to run.

Example:

```text
R
```

---

## S — Sleeping

The process is waiting for something.

For example:

```text
Waiting for network response
Waiting for user input
Waiting for disk operation
```

Most processes spend a lot of time in this state.

---

## D — Uninterruptible Sleep

Usually waiting for I/O.

For example:

```text
Disk
Network storage
Hardware
```

A process in `D` state may not respond immediately to normal signals.

---

## T — Stopped

The process has been stopped.

For example:

```bash
Ctrl + Z
```

can stop a foreground process.

---

## Z — Zombie

A zombie process has completed execution but still has an entry in the process table because its parent has not collected its exit status.

More on this later.

# 11. Foreground and Background Processes

Linux processes can run in:

```text
Foreground
Background
```

## Foreground

When you run:

```bash
ping google.com
```

the command occupies your terminal.

You cannot easily enter another command in the same terminal until it finishes or you stop/background it.

---

## Background

You can run a command in the background using:

```bash
ping google.com &
```

Example:

```text
ping google.com &
```

The terminal becomes available again.

# 12. Daemon Processes

A **daemon** is a background process that usually provides a service.

Examples:

```text
sshd
cron
systemd-journald
nginx
docker
```

A daemon often:

- starts automatically
- runs in the background
- waits for requests/events
- provides a service

Example:

```text
Client
   |
   ↓
SSH Request
   |
   ↓
sshd
   |
   ↓
User Session
```

# 13. Process Tree

Processes have parent-child relationships.

Example:

```text
systemd
 |
 +---- sshd
 |      |
 |      +---- bash
 |            |
 |            +---- ps
 |
 +---- cron
 |
 +---- nginx
 |
 +---- java
```

This is called a **process tree**.

You can view it using:

```bash
pstree
```

# 15. `ps` Command

`ps` means:

> Process Status

Basic command:

```bash
ps
```

Example:

```text
PID TTY          TIME CMD
2501 pts/0    00:00:00 bash
2901 pts/0    00:00:00 ps
```

---

## Show all processes

```bash
ps aux
```

This is one of the most commonly used commands in Linux troubleshooting.

Example:

```bash
ps aux
```

Possible output:

```text
USER       PID %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
root         1  0.0  0.1  ...
appuser   2456 35.5  8.2  ...
mysql     3000 12.2 15.4  ...
```

Important columns:

| Column | Meaning |
|---|---|
| USER | Process owner |
| PID | Process ID |
| %CPU | CPU usage |
| %MEM | Memory usage |
| VSZ | Virtual memory |
| RSS | Physical memory |
| STAT | Process state |
| START | Start time |
| TIME | CPU time |
| COMMAND | Command/process |

---

## Show processes in full format

```bash
ps -ef
```

This is particularly useful for checking:

```text
PID
PPID
User
Command
```

Example:

```text
UID       PID  PPID  CMD
root        1     0  /sbin/init
appuser  2500     1  java -jar app.jar
```

---

## Find a process

```bash
ps aux | grep java
```

Example:

```text
appuser  2500  20.0  8.0  java -jar app.jar
```

This is a common troubleshooting command.

> Note: `grep` itself may appear in the output. Tools such as `pgrep -af java` can be cleaner.

| Column | Meaning |
|---|---|

| PR | Priority |

# 21. Background Jobs

A job is a task started from your shell.

Example:

```bash
sleep 100
```

This runs in the foreground.

Press:

```text
Ctrl + Z
```

The process becomes stopped.

You may see:

```text
[1]+  Stopped  sleep 100
```

Now you can move it to the background.

---

# 22. `jobs` Command

Show jobs associated with the current shell:

```bash
jobs
```

Example:

```text
[1]+  Stopped    sleep 100
```

---

# 23. `bg` Command

Move a stopped job to the background:

```bash
bg %1
```

Example:

```text
[1]+ sleep 100 &
```

The job continues running in the background.

---

# 24. `fg` Command

Bring a background/stopped job to the foreground:

```bash
fg %1
```

Now the process is attached to your terminal again.

---

# 25. `&` Background Operator

You can directly start a command in the background:

```bash
sleep 100 &
```

Example:

```text
[1] 4500
```

Here:

```text
1    = shell job number
4500 = PID
```

Check:

```bash
jobs
```

or:

```bash
ps -p 4500
```

# 26. `nohup` Command

Normally, a process started from a terminal may stop when the terminal/session closes.

`nohup` helps a command continue after logout.

Example:

```bash
nohup ./backup.sh &
```

Output is commonly written to:

```text
nohup.out
```

Example:

```bash
nohup java -jar application.jar > app.log 2>&1 &
```

This means:

```text
Start Java application
        |
        +---- Continue after terminal closes
        |
        +---- Write output to app.log
        |
        +---- Run in background
```

### Important

In modern production environments, long-running applications are generally better managed by:

```text
systemd
Docker
Kubernetes
Process managers
```

rather than manually using `nohup`.

# 27. Signals

Linux uses **signals** to communicate with processes.

A signal is like a message sent to a process.

Example:

```text
Application
     ↑
   Signal
     ↑
Operating System
```

Signals can tell a process to:

```text
Stop
Continue
Terminate
Reload
Interrupt
```

---

# 28. `kill` Command

Despite its name, `kill` does not always mean "forcefully kill".

It actually means:

> Send a signal to a process.

Syntax:

```bash
kill PID
```

Example:

```bash
kill 2500
```

By default, this normally sends:

```text
SIGTERM
```

---

# 29. `kill -15`

`SIGTERM` is signal number 15.

```bash
kill -15 2500
```

or:

```bash
kill -TERM 2500
```

It politely asks the process to terminate.

The application gets a chance to:

```text
Close connections
Save data
Flush logs
Release resources
Shutdown gracefully
```

This should generally be your first choice when stopping a process manually.

---

# 30. `kill -9`

`SIGKILL` is signal 9.

```bash
kill -9 2500
```

It forcefully terminates the process.

The process does not get an opportunity to perform normal cleanup.

### Use carefully.

Do not make this your first command.

Preferred approach:

```text
1. Check process
2. Try graceful stop
3. Wait
4. Investigate if it does not stop
5. Use SIGKILL only when justified
```

---

# 31. `pkill`

`pkill` allows you to send signals based on process name.

Example:

```bash
pkill nginx
```

This can affect multiple matching processes.

Safer investigation:

```bash
pgrep -af nginx
```

Then decide what should be stopped.

---

# 32. `killall`

Example:

```bash
killall nginx
```

This sends a signal to matching processes.

Again, be careful because multiple processes can match.

---

# 33. Important Linux Signals

| Signal | Number | Purpose |
|---|---:|---|
| SIGHUP | 1 | Hangup / reload behavior for some applications |
| SIGINT | 2 | Interrupt |
| SIGQUIT | 3 | Quit |
| SIGKILL | 9 | Force kill |
| SIGTERM | 15 | Graceful termination |
| SIGSTOP | 19 | Stop process |
| SIGCONT | 18 | Continue stopped process |

---

## SIGINT

Usually generated by:

```text
Ctrl + C
```

Example:

```bash
ping google.com
```

Press:

```text
Ctrl + C
```

The process receives an interrupt signal.

---

## SIGSTOP

Stop a process:

```bash
kill -STOP 2500
```

---

## SIGCONT

Continue a stopped process:

```bash
kill -CONT 2500
```

# 34. Process Priority

Linux allows processes to have different priorities.

The concept is useful when multiple processes compete for CPU.

Important values include:

```text
Priority
Nice value
```

---

# 35. `nice`

`nice` starts a process with a specified nice value.

Example:

```bash
nice -n 10 ./backup.sh
```

A higher nice value generally means the process is more willing to give CPU time to other processes.

Typical nice range:

```text
-20  → higher priority
  0  → default
+19  → lower priority
```

Changing to higher priority may require elevated privileges.

---

# 36. `renice`

`renice` changes the nice value of an existing process.

Example:

```bash
renice 10 -p 2500
```

This changes the priority behavior of PID `2500`.

Check using:

```bash
ps -o pid,ni,cmd -p 2500
```

### Production caution

Do not change process priority randomly on production servers.

First understand:

```text
Why is CPU high?
Which process is affected?
What is the business impact?
What is the approved change?
```

# 37. CPU Usage

CPU usage tells us how much CPU a process is consuming.

Example:

```text
PID    %CPU    COMMAND
2500   85.5    java
3000   10.2    mysql
```

Here:

```text
Java process = high CPU consumer
```

Check using:

```bash
top
```

or:

```bash
ps aux --sort=-%cpu | head
```

This is useful when investigating:

> "Why is the server CPU usage 95%?"

---

# 38. Memory Usage

Check memory-consuming processes:

```bash
ps aux --sort=-%mem | head
```

Example:

```text
USER      PID   %MEM   COMMAND
appuser  2500   25.5   java
mysql    3000   15.2   mysqld
```

You can also use:

```bash
top
```

and press:

```text
M
```

to sort by memory.

---

# 39. Zombie Process

A zombie process is a process that has finished execution but still has an entry in the process table because its parent has not collected its exit status.

Conceptually:

```text
Parent
  |
  +---- Child
          |
       Finished
          |
       Zombie
```

Check:

```bash
ps aux | grep Z
```

or:

```bash
ps -eo pid,ppid,state,cmd | grep Z
```

You may see:

```text
2500  2000  Z  [process] <defunct>
```

`<defunct>` usually indicates a zombie.

### Important

You normally cannot "kill" a zombie directly because it has already exited.

The real issue is usually the parent process.

---

# 40. Orphan Process

An orphan process is a process whose parent has exited while the child continues running.

Example:

```text
Parent
  |
  +---- Child
```

Parent exits:

```text
Parent ❌
  |
  +---- Child
```

Linux re-parents the orphan process to another process, traditionally PID 1 or an appropriate subreaper.

Modern Linux systems commonly use `systemd` as PID 1.

---

# 41. `lsof`

`lsof` means:

> List Open Files

Linux treats many resources as files, so `lsof` is extremely useful.

Check files opened by a process:

```bash
lsof -p 2500
```

Find which process is using a file:

```bash
lsof /var/log/application.log
```

---

## Find process using a port

For example:

```bash
sudo lsof -i :8080
```

Possible output:

```text
COMMAND PID     USER   FD   TYPE DEVICE SIZE/OFF NODE NAME
java    2500    appuser 123u IPv6 ...    TCP *:8080 (LISTEN)
```

Now we know:

```text
Port = 8080
Process = java
PID = 2500
User = appuser
```

---

# 42. `fuser`

`fuser` identifies processes using a resource.

Example:

```bash
sudo fuser 8080/tcp
```

Possible output:

```text
8080/tcp: 2500
```

Meaning:

```text
PID 2500 is using TCP port 8080
```

---

# 43. Finding Which Process Uses a Port

This is a very common Application Support problem.

Suppose your application needs:

```text
Port 8080
```

but startup fails:

```text
Address already in use
```

First check:

```bash
sudo ss -lntp | grep :8080
```

You can also use:

```bash
sudo lsof -i :8080
```

or:

```bash
sudo fuser 8080/tcp
```

Then identify the process.

Example:

```text
java 2500 appuser TCP *:8080 (LISTEN)
```

Now investigate:

```bash
ps -fp 2500
```

This gives more information about the process.

# 45. Scenario 1: Application is Slow

### Problem

Users report:

> "Application is very slow."

### Step 1 — Check server resources

```bash

```

# 50. Production Safety Rules

Process management commands can affect production systems.

Always follow these rules.

## Rule 1 — Never blindly kill a process

Do not run:

```bash
kill -9 <PID>
```

without understanding the process.

---

## Rule 2 — Check the process first

Use:

```bash
ps -fp <PID>
```

---

## Rule 3 — Identify the owner

Check:

```bash
ps -o user,pid,ppid,stat,%cpu,%mem,cmd -p <PID>
```

---

## Rule 4 — Prefer graceful termination

Prefer:

```bash
kill -15 <PID>
```

before:

```bash
kill -9 <PID>
```

when appropriate.

---

## Rule 5 — Follow change procedures

In production:

```text
Ticket
  ↓
Approval
  ↓
Implementation
  ↓
Verification
```

Do not make unauthorized changes.

---

## Rule 6 — Be careful with root processes

A root process may be:

```text
SSH
systemd
Networking
Security
Logging
Database
```

Killing the wrong process can affect the entire server.

```bash
kill 5000
```

```text
kill: (5000): No such process
```

Possible reason:

```text
Process already stopped
Wrong PID
Process restarted with another PID
```

Check:

```bash
ps -p 5000
```

## Error 2 — Permission Denied

You may see:

```text
Operation not permitted
```

The process may belong to another user.

Check:

```bash
ps -fp <PID>
```

If approved and necessary, use appropriate privileges:

```bash

```

Do not use `sudo` automatically.

```bash
kill -15 <PID>
```

```bash
ps -fp <PID>
```

```bash
top
```

```bash
kill -9 <PID>
```

# 🎯 Final Mindset

As an Application Support Engineer, do not think:

> "The application is slow, so kill the process."

Instead, think:

```text
What is happening?
        ↓
Which process is involved?
        ↓
Who owns it?
        ↓
How much CPU is it using?
        ↓
How much memory is it using?
        ↓
Which port is it using?
        ↓
What do the logs say?
        ↓
Is the behavior expected?
        ↓
What is the root cause?
        ↓
What is the safest approved action?
        ↓
Did the application recover?
```

That is the difference between simply knowing Linux commands and **actually troubleshooting Linux production systems**.

> 💡 **Remember:** In production, commands are tools. Understanding the problem comes first.
