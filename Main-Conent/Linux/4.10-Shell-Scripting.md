# 1. Introduction

Linux provides hundreds of commands.

For example:

```bash
pwd
ls
df -h
free -m
ps
systemctl
journalctl
grep
find
```

Running these commands manually is fine when troubleshooting one server.

But imagine you have:

```text
10 servers
50 servers
100 servers
500 servers
```

Running the same commands manually becomes slow and error-prone.

This is where **Shell Scripting** becomes useful.

Instead of repeatedly typing:

```bash
hostname
date
uptime
df -h
free -m
```

we can create one script:

```bash
./server-health.sh
```

The script performs the same tasks automatically.

---

# 2. What is Shell Scripting?

A **shell script** is a text file containing a sequence of shell commands that can be executed as a program.

Example:

```bash
#!/bin/bash

echo "Server Information"
hostname
date
uptime
```

Save it as:

```text
server-info.sh
```

Then execute:

```bash
./server-info.sh
```

The shell executes the commands one after another.

---

# 3. Why Do We Need Shell Scripts?

Shell scripting helps with:

- automation
- repetitive tasks
- server monitoring
- log collection
- backups
- file management
- application health checks
- deployment tasks
- service checks
- disk monitoring
- process monitoring
- user management
- scheduled tasks

### Without scripting

```text
Run command
   ↓
Read result
   ↓
Run another command
   ↓
Repeat
   ↓
Repeat
   ↓
Repeat
```

### With scripting

```text
Run Script
   ↓
Multiple tasks execute automatically
   ↓
Generate result
```

# 4. Shell Script in Application Support

Application Support engineers frequently automate repetitive checks.

For example:

> "Check whether the application is running, check disk usage, check memory, check the application port, and collect recent logs."

Instead of running:

```bash
systemctl status myapp
df -h
free -m
ss -lntp
journalctl -u myapp -n 50
```

we can create:

```bash
./app-health-check.sh
```

The script can produce:

```text
================================
 Application Health Check
================================

Service: RUNNING
Disk: OK
Memory: OK
Port: LISTENING
Recent Errors: 0
```

This is a very common automation pattern.

# 7. The Shebang

The first line is usually:

```bash
#!/bin/bash
```

This is called the **shebang**.

It tells the operating system which interpreter should execute the script.

For Bash:

```bash
#!/bin/bash
```

Another portable approach is:

```bash
#!/usr/bin/env bash
```

For beginner Bash scripts, you will commonly see:

```bash
#!/bin/bash
```

---

# 8. Script Comments

Comments are ignored by the shell.

Example:

```bash
#!/bin/bash

# Display the server hostname
hostname

# Display current date
date
```

A comment begins with:

```text
#
```

Comments are important because they explain why the script is doing something.

# 9. Running a Shell Script

There are several ways to execute a script.

## Method 1 — Bash

```bash
bash hello.sh
```

This does not require the script itself to have execute permission.

---

## Method 2 — Make Executable

```bash
chmod +x hello.sh
```

Then:

```bash
./hello.sh
```

---

## Method 3 — Absolute Path

```bash
/home/user/scripts/hello.sh
```

if executable.

# 10. Script Permissions

Check:

```bash
ls -l hello.sh
```

Example:

```text
-rwxr-xr-x
```

The `x` permission means executable.

Add execute permission:

```bash
chmod +x hello.sh
```

Remove execute permission:

```bash
chmod -x hello.sh
```

```bash
#!/bin/bash
```

Correct:


```bash

```

# 16. Command Substitution

# 17. Arithmetic Operations

Bash can perform basic arithmetic.

Use:

```bash
$(( ))
```

Example:

```bash
a=10
b=5

sum=$((a + b))

echo "$sum"
```

Output:

```text
15
```

Other operations:

```bash
a=10
b=5

echo $((a + b))
echo $((a - b))
echo $((a * b))
echo $((a / b))
echo $((a % b))
```

| `-lt` | Less than |
| `-ge` | Greater/equal |

# 20. File and Directory Checks

Important operators:

| Operator | Meaning |
|---|---|
| `-f` | Regular file exists |
| `-d` | Directory exists |
| `-e` | Path exists |
| `-r` | Readable |
| `-w` | Writable |
| `-x` | Executable |
| `-s` | File exists and is not empty |

Example:

```bash
if [ -f "/etc/passwd" ]; then
    echo "File exists"
fi
```

Directory:

```bash
if [ -d "/var/log" ]; then
    echo "Directory exists"
fi
```

# 21. String Comparisons

Example:

```bash
name="Sahil"

if [ "$name" = "Sahil" ]; then
    echo "Name matched"
fi
```

Not equal:

```bash
if [ "$name" != "Rahul" ]; then
    echo "Different name"
fi
```

Check empty string:

```bash
if [ -z "$name" ]; then
    echo "Name is empty"
fi
```

Check non-empty:

```bash
if [ -n "$name" ]; then
    echo "Name is not empty"
fi
```

# 22. `if` Statement

Basic syntax:

```bash
if [ condition ]; then
    commands
fi
```

Example:

```bash
#!/bin/bash

age=20

if [ "$age" -ge 18 ]; then
    echo "Adult"
fi
```

---

# 23. `if-else` Statement

```bash
#!/bin/bash

age=16

if [ "$age" -ge 18 ]; then
    echo "Adult"
else
    echo "Minor"
fi
```

---

# 24. `if-elif-else`

Use `elif` when multiple conditions exist.

```bash
#!/bin/bash

score=75

if [ "$score" -ge 90 ]; then
    echo "Excellent"
elif [ "$score" -ge 70 ]; then
    echo "Good"
elif [ "$score" -ge 50 ]; then
    echo "Pass"
else
    echo "Fail"
fi
```

---

# 25. Nested Conditions

An `if` can exist inside another `if`.

Example:

```bash
#!/bin/bash

if [ -f "/etc/passwd" ]; then

    if [ -r "/etc/passwd" ]; then
        echo "File exists and is readable"
    fi

fi
```

Avoid deeply nested conditions when possible because they make scripts harder to maintain.

---

# 26. `case` Statement

`case` is useful when one variable can have several known values.

Example:

```bash
#!/bin/bash

read -p "Enter environment: " environment

case "$environment" in
    production)
        echo "Production environment"
        ;;
    staging)
        echo "Staging environment"
        ;;
    development)
        echo "Development environment"
        ;;
    *)
        echo "Unknown environment"
        ;;
esac
```

---

## Application Support Example

```bash
#!/bin/bash

read -p "Enter action: " action

case "$action" in
    start)
        echo "Starting application"
        ;;
    stop)
        echo "Stopping application"
        ;;
    restart)
        echo "Restarting application"
        ;;
    status)
        echo "Checking application"
        ;;
    *)
        echo "Invalid action"
        ;;
esac
```

# 27. `for` Loop

A `for` loop repeats commands.

Example:

```bash
#!/bin/bash

for name in Sahil Rahul Priya
do
    echo "Hello $name"
done
```

Output:

```text
Hello Sahil
Hello Rahul
Hello Priya
```

---

## Loop Through Files

```bash
for file in /var/log/*.log
do
    echo "$file"
done
```

Be careful with assumptions about filenames and empty matches in production scripts.

---

## Loop Through Numbers

```bash
for i in 1 2 3 4 5
do
    echo "Number: $i"
done
```

---

# 28. `while` Loop

A `while` loop runs while a condition remains true.

Example:

```bash
#!/bin/bash

count=1

while [ "$count" -le 5 ]
do
    echo "Count: $count"
    count=$((count + 1))
done
```

Output:

```text
Count: 1
Count: 2
Count: 3
Count: 4
Count: 5
```

---

# 29. `break` and `continue`

## `break`

Stops the loop.

```bash
for i in 1 2 3 4 5
do
    if [ "$i" -eq 3 ]; then
        break
    fi

    echo "$i"
done
```

Output:

```text
1
2
```

---

## `continue`

Skips the current iteration.

```bash
for i in 1 2 3 4 5
do
    if [ "$i" -eq 3 ]; then
        continue
    fi

    echo "$i"
done
```

Output:

```text
1
2
4
5
```

# 32. Return Status

Functions can return a status.

Example:

```bash
check_file() {
    if [ -f "$1" ]; then
        return 0
    else
        return 1
    fi
}
```

Use:

```bash
if check_file "/etc/passwd"; then
    echo "File exists"
else
    echo "File does not exist"
fi
```

Remember:

```text
0 = success
non-zero = failure
```

---

# 33. Exit Status

A script can explicitly exit with a status.

Success:

```bash
exit 0
```

Failure:

```bash
exit 1
```

Example:

```bash
#!/bin/bash

if [ -f "/etc/passwd" ]; then
    echo "File found"
    exit 0
else
    echo "File not found"
    exit 1
fi
```

This is useful for automation systems.

For example, monitoring software can determine:

```text
0 → healthy
non-zero → problem
```

# 34. Pipes and Redirection

Shell scripts can use the same operators as interactive commands.

## Pipe

```bash
ps aux | grep nginx
```

Output from the first command becomes input to the second.

---

## Redirect Output

```bash
echo "Server check" > server.log
```

This creates/overwrites the file.

Append:

```bash
echo "Another check" >> server.log
```

---

## Redirect Errors

```bash
command 2> error.log
```

Both output and errors:

```bash
command > output.log 2>&1
```

A common modern Bash form is:

```bash
command &> output.log
```

Use the form that is appropriate for the shell your script targets.

# 35. Logging in Shell Scripts

Logging is important for support automation.

Example:

```bash
#!/bin/bash

LOG_FILE="/tmp/app-check.log"

echo "$(date) - Script started" >> "$LOG_FILE"
```

For production, choose an appropriate log location and consider log rotation.

# 37. Safe Shell Scripting

For serious Bash scripts, you may see:

```bash
set -euo pipefail
```

This is useful but should be understood rather than blindly copied.

---

## `set -e`

Causes the script to exit when a command fails in many common situations.

```bash
set -e
```

---

## `set -u`

Treats unset variables as errors.

```bash
set -u
```

---

## `set -o pipefail`

Makes a pipeline fail when an earlier command in the pipeline fails.

```bash
set -o pipefail
```

Together:

```bash
set -euo pipefail
```

However, Bash has edge cases around these options, especially `set -e`. Production scripts should be tested carefully.

---

## Quote Variables

Prefer:

```bash
rm -- "$file"
```

over:

```bash
rm $file
```

Quoting protects against spaces and many special-character problems.

---

## Avoid Dangerous Wildcards

Be careful with commands such as:

```bash
rm -rf *
```

Never use destructive commands without understanding exactly what path and expansion they target.

# Example 2 — Service Health Check

```bash
#!/bin/bash

SERVICE="nginx"

if systemctl is-active --quiet "$SERVICE"; then
    echo "$SERVICE is running"
else
    echo "$SERVICE is NOT running"
    exit 1
fi
```

Run:

```bash
./service-check.sh
```

---

# Example 3 — Disk Usage Alert

```bash
#!/bin/bash

THRESHOLD=80

USAGE=$(df -P / | awk 'NR==2 {gsub("%","",$5); print $5}')

echo "Disk usage: ${USAGE}%"

if [ "$USAGE" -ge "$THRESHOLD" ]; then
    echo "WARNING: Disk usage is high"
    exit 1
else
    echo "Disk usage is normal"
    exit 0
fi
```

This pattern can be used as the foundation of a monitoring check.

---

# Example 4 — Check Application Port

```bash
#!/bin/bash

PORT=8080

if ss -lnt | grep -q ":$PORT "; then
    echo "Port $PORT is listening"
else
    echo "Port $PORT is NOT listening"
    exit 1
fi
```

Always test the matching logic against your actual `ss` output before using it in production.

---

# Example 5 — Check Multiple Services

```bash
#!/bin/bash

SERVICES=("nginx" "ssh")

for service in "${SERVICES[@]}"
do
    if systemctl is-active --quiet "$service"; then
        echo "$service: OK"
    else
        echo "$service: FAILED"
    fi
done
```

# 41. Common Errors

## Error 1 — Permission Denied

You run:

```bash
./script.sh
```

and receive:

```text
Permission denied
```

Fix:

```bash
chmod +x script.sh
```

or run:

```bash
bash script.sh
```

---

# Error 2 — Bad Interpreter

You may see:

```text
bad interpreter
```

Possible causes include:

- incorrect shebang
- Windows line endings
- incorrect interpreter path

Check:

```bash
head -n 1 script.sh
```

If a script was created on Windows, line endings may need conversion before Linux execution.

---

# Error 3 — Command Not Found

Example:

```text
command not found
```

Check:

```bash
which command
```

and:

```bash
echo "$PATH"
```

---

# Error 4 — Variable Empty

Example:

```bash
echo "$APP_ENV"
```

returns nothing.

Check:

```bash
printenv APP_ENV
```

Then investigate whether the variable was exported and whether the correct startup/configuration file was loaded.

---

# Error 5 — Incorrect Condition

Bad:

```bash
if [ $name = Sahil ]; then
```

Safer:

```bash
if [ "$name" = "Sahil" ]; then
```

Quoting variables helps prevent errors when values contain spaces or are empty.

---

# Error 6 — Script Works Manually but Not from Cron

Possible reasons:

```text
Different PATH
Different working directory
Different environment
Different user
Relative paths
Missing permissions
```

Use absolute paths where appropriate and explicitly configure the environment needed by the script.

This is a very common production issue.

---

# Error 7 — Script Works Manually but Not from Systemd

Again, the service environment may differ from your login shell.

Check:

```bash
systemctl cat your-service
```

and:

```bash
systemctl show your-service --property=Environment
```
