# 1. Introduction

Every Linux server contains thousands or millions of files.

For example, an application server may contain:

```text
Application Files
Configuration Files
Log Files
Temporary Files
Database Files
Backup Files
Scripts
Certificates
Libraries
System Files
```

As an Application Support Engineer, you will regularly perform tasks such as:

```text
Find a configuration file
Read application logs
Search errors inside logs
Create directories
Copy configuration files
Move files
Rename files
Delete temporary files
Find large files
Check disk usage
Create log backups
Compress files
Extract archives
```

Therefore, **File & Directory Management** is one of the most important Linux skills.

---

# 2. What is a File?

A file is a container used to store information.

Examples:

```text
application.log
application.conf
server.properties
backup.sql
script.sh
index.html
data.json
```

A file can contain:

```text
Text
Configuration
Logs
Code
Images
Binary data
Database data
```

---

# 3. What is a Directory?

A directory is a container used to organize files and other directories.

In Windows, we commonly say:

```text
Folder
```

In Linux, the standard term is:

```text
Directory
```

Example:

```text
/var/log/
    |
    +-- application.log
    +-- error.log
    +-- access.log
```

Here:

```text
/var/log/
```

is a directory.

---

# 4. Linux Everything is a File

One of the important Linux concepts is:

> Many resources are represented through the filesystem interface.

Regular files are obvious, but Linux also exposes things such as:

```text
Devices
Sockets
Pipes
Special system interfaces
```

through file-like interfaces.

For example:

```text
/dev/
```

contains device-related entries.

This design is one reason Linux commands can work consistently with many types of resources.

---

# 5. Linux File System Structure

Linux uses a hierarchical filesystem.

At the top is:

```text
/
```

This is called the **root directory**.

Example:

```text
/
├── bin
├── boot
├── dev
├── etc
├── home
├── lib
├── opt
├── proc
├── root
├── run
├── sbin
├── tmp
├── usr
└── var
```

Everything starts from:

```text
/
```

---

# 6. Important Linux Directories

| Directory | Purpose |
|---|---|
| `/` | Root of filesystem |
| `/home` | Normal users' home directories |
| `/root` | Root user's home directory |
| `/etc` | System/application configuration |
| `/var` | Variable data such as logs |
| `/var/log` | Log files |
| `/tmp` | Temporary files |
| `/opt` | Optional/third-party applications |
| `/usr` | User-space programs and libraries |
| `/bin` | Essential commands on many systems |
| `/sbin` | System administration commands |
| `/dev` | Device files |
| `/proc` | Process/kernel information |
| `/run` | Runtime system information |
| `/boot` | Boot-related files |
| `/mnt` | Temporary mount point |
| `/media` | Removable media mount points |

### Important

The exact contents can vary between Linux distributions and modern filesystem layouts.

# 7. File Paths

A path tells Linux where a file or directory is located.

Example:

```text
/var/log/application.log
```

Breakdown:

```text
/
└── var
    └── log
        └── application.log
```

A path can be:

```text
Absolute
Relative
```

---

# 8. Absolute Path

An absolute path starts from:

```text
/
```

Example:

```text
/var/log/application.log
```

Another example:

```text
/home/sahil/project/app.py
```

Absolute paths always describe the location from the filesystem root.

---

# 9. Relative Path

A relative path is based on the current directory.

Suppose:

```text
Current directory:
/home/sahil/project
```

Then:

```text
logs/app.log
```

means:

```text
/home/sahil/project/logs/app.log
```

Relative paths are useful when working inside a project.

---

# 10. Home Directory

Every normal Linux user generally has a home directory.

Example:

```text
/home/sahil
```

You can check it using:

```bash
echo $HOME
```

Go to your home directory:

```bash
cd ~
```

or simply:

```bash
cd
```

---

# 11. Current Directory

Check the current directory:

```bash
pwd
```

Example:

```text
/home/sahil/projects
```

`pwd` means:

> Print Working Directory

---

# 12. Root Directory vs Root User

These are different concepts.

## Root Directory

```text
/
```

The top-level directory of the filesystem.

## Root User

```text
root
```

The administrative user.

So:

```text
/      → root directory
root   → administrative user
```

Do not confuse them.


```text
.
```

```text
.
```

means current directory.

```text
..
```

# 17. Creating Files

Use `touch`:

```bash
touch application.log
```

Create multiple files:

```bash
touch app.log error.log access.log
```

Create a file with content using `echo`:

```bash
echo "Application started" > app.log
```

Be careful:

```text
>
```

overwrites an existing file.

Whereas:

```text
>>
```

appends to the file.

Example:

```bash
echo "Application started" >> app.log
```

Use:

```bash

```

Example:


## Interactive deletion

```bash
rm -i test.txt
```

---

# 24. Deleting Directories

Empty directory:

```bash
rmdir test
```

Directory containing files:

```bash
rm -r test
```

Force removal:

```bash
rm -rf test
```

### ⚠️ Very Important

Be extremely careful with:

```bash
rm -rf
```

Especially:

```bash
sudo rm -rf
```

A wrong path can cause serious damage.

Always verify:

```bash
pwd
ls
```

before destructive commands.

For large files:

```bash

```

Useful controls:

```text
Space      → next page

```


`less` is generally more capable and commonly preferred.

Display 20 lines:

```bash

```

# 30. `tail`

Display the end of a file:

```bash

```

Useful for logs.

Example:

```bash
tail -n 50 application.log
```

This displays the last 50 lines.

# 31. Monitoring Logs with `tail -f`

This is one of the most important Application Support commands.

```bash
tail -f application.log
```

It continuously displays new lines added to the file.

Example:

```text
Application started
User login successful
Payment request received
Database connection established
```

When a new log entry is written:

```text
Payment completed
```

it appears automatically.

Stop with:

```text
Ctrl + C
```

# 32. Searching Inside Files with `grep`

`grep` searches text.

Example:

```bash
grep "ERROR" application.log
```

This finds lines containing:

```text
ERROR
```

---

## Case-insensitive search

```bash
grep -i "error" application.log
```

---

## Show line numbers

```bash
grep -n "ERROR" application.log
```

Example:

```text
145:ERROR Database connection failed
```

---

## Count matches

```bash
grep -c "ERROR" application.log
```

---

## Search recursively

```bash
grep -r "ERROR" /var/log/myapp/
```

Be mindful of permissions and the size of the directory being searched.

---

# 33. Combining `grep` with Other Commands

Linux becomes powerful when commands are combined.

Example:

```bash
ps aux | grep java
```

Meaning:

```text
ps aux
   ↓
Show processes
   ↓
|
   ↓
grep java
   ↓
Show only lines containing java
```

Another example:

```bash
ls -l /var/log | grep application
```

Another:

```bash
grep "ERROR" application.log | tail
```

This means:

```text
Find ERROR
   ↓
Show matching lines
   ↓
Display the last few
```

# 34. Finding Files with `find`

`find` is one of the most useful Linux commands.

Basic:

```bash
find /path -name filename
```

Example:

```bash
find /var/log -name "application.log"
```

---

## Find by extension

```bash
find /var/log -name "*.log"
```

---

## Case-insensitive filename search

```bash
find /var/log -iname "*.LOG"
```

---

## Find directories

```bash
find /var/log -type d -name "backup"
```

---

## Find files

```bash
find /var/log -type f -name "*.log"
```

---

## Find large files

Example:

```bash

```

## Find recently modified files

```bash

```

This searches for files modified within approximately the last day.

# 36. File Types

Linux commonly identifies files using the first character in `ls -l`.

Example:



Common types:

| Symbol | Type |
|---|---|
| `-` | Regular file |

| `l` | Symbolic link |
| `c` | Character device |
| `b` | Block device |
| `s` | Socket |
| `p` | Named pipe |

# 37. `file` Command

The `file` command identifies the type of a file.

Example:

```bash
file application.log
```

Another:

```bash

```

Example output might indicate:

```text

```

This is useful when a file extension is misleading or missing.

# 38. Symbolic Links

A symbolic link is a reference to another file or directory.

Example:

```text
application.log
     ↑
     |
logs/current.log
```

Create:

```bash
ln -s /var/log/application.log current.log
```

Check:

```bash
ls -l current.log
```

Output may look like:

```text
current.log -> /var/log/application.log
```

---

## Why symbolic links are useful

They can provide stable paths.

Example:

```text
/opt/app/current
```

could point to:

```text
/opt/app/releases/v2.5
```

Later:

```text
/opt/app/current
```

can point to:

```text
/opt/app/releases/v2.6
```

This pattern is common in deployment systems.

---

# 39. Hard Links

A hard link is another directory entry referring to the same underlying inode/data.

Create:

```bash
ln original.txt copy.txt
```

Both names refer to the same underlying file data.

Hard links have limitations and generally cannot be created across different filesystems.

For beginners:

```text
Symbolic link
    ↓
Points to a path

Hard link
    ↓
Another name for the same underlying file
```

Access time.

When the file was accessed.

### mtime

---

---

# 45. `df`

`df` shows filesystem disk space.

Use:

```bash
df -h
```

Example:

```text
Filesystem      Size  Used Avail Use%
/dev/sda1       100G   82G   18G  83%
```

Difference:

```text
df → filesystem free/used space
du → directory/file usage
```

This distinction is extremely important.

# 47. `tar`

`tar` creates archives.

Create archive:

```bash
tar -cvf backup.tar project/
```

Options:

```text
c = create
v = verbose
f = filename
```

Extract:

```bash
tar -xvf backup.tar
```

Options:

```text
x = extract
```

---

## Create gzip-compressed tar archive

```bash
tar -czvf backup.tar.gz project/
```

Here:

```text
c = create
z = gzip
v = verbose
f = file
```

Extract:

```bash
tar -xzvf backup.tar.gz
```

---

## List archive contents

```bash
tar -tzf backup.tar.gz
```

This lets you inspect the archive before extracting it.

---

# 48. `gzip`

Compress a file:

```bash
gzip application.log
```

This normally creates:

```text
application.log.gz
```

Decompress:

```bash
gunzip application.log.gz
```

# 51. Scenario 1: Find an Application Log

Suppose you know:

```text
Application = payment-service
```

but you don't know where its log file is.

Search:

```bash
find /var/log -type f -iname "*payment*"
```

If application files may be under `/opt`:

```bash
find /opt -type f -iname "*.log" 2>/dev/null
```

Then inspect:

```bash
less /path/to/application.log
```

---

# 52. Scenario 2: Log File is Growing Quickly

Monitoring reports:

```text
Disk usage increasing
```

Check:

```bash
df -h
```

Then:

```bash
du -sh /var/log/*
```

Find large log files:

```bash
find /var/log -type f -size +500M -ls
```

Inspect:

```bash
ls -lh /path/to/log
```

Then investigate why the log is growing.

Possible reasons:

```text
Application error loop
Debug logging enabled
Traffic spike
Misconfigured logging
Repeated connection failures
```

Do not simply delete the log without understanding the logging/retention process.

---

# 53. Scenario 3: Disk is Full

Suppose monitoring reports:

```text
Filesystem usage = 98%
```

First:

```bash
df -h
```

Identify the affected filesystem.

Then investigate directories:

```bash
du -xhd1 / 2>/dev/null
```

Or if the issue is under `/var`:

```bash
du -xhd1 /var 2>/dev/null
```

Find large files:

```bash
find /var -xdev -type f -size +1G -ls 2>/dev/null
```

Investigate:

```text
Which file?
Who owns it?
Is it a log?
Is it required?
Is there an approved retention policy?
Can it be archived?
```

# 54. Scenario 4: Search for an Error

Suppose users report payment failures.

Search:

```bash
grep -i "error" application.log
```

Search specific error:

```bash
grep -i "database connection" application.log
```

Include line numbers:

```bash
grep -in "database connection" application.log
```

Search multiple log files:

```bash
grep -Rin "database connection" /var/log/payment/
```

## Search multiple patterns

```bash
grep -Ei "error|exception|failed|timeout" application.log
```

This is extremely useful during incident investigation.

# 57. Common Errors

```bash
cat application.log
```


Check:

```bash
pwd
ls
```

Then search:

```bash
find . -name "application.log"
```

---

## Error 2 — Permission denied

Example:

```bash
cat /var/log/somefile.log
```

Output:

```text
Permission denied
```

Check:

```bash
ls -l /var/log/somefile.log
```

Understand:

```text
Owner
Group
Permissions
```

Do not immediately use:

```bash
sudo
```

without understanding why access is denied.

---

## Error 3 — Cannot remove directory

You may see:

```text
Directory not empty
```

Use:

```bash
ls directory
```

If appropriate:

```bash
rm -r directory
```

Be very careful with recursive deletion.

---

## Error 4 — Disk full

Check:

```bash
df -h
```

Then:

```bash
du -sh /*
```

For a large system, narrow the investigation rather than scanning everything unnecessarily.

---

## Error 5 — File exists

Example:

```bash
mkdir project
```

Output:

```text
File exists
```

Check:

```bash
ls -ld project
```

Then decide whether you need to use:

```bash
cd project
```

or create a different directory.



## Rule 3 — Be careful with `rm -rf`


## Rule 4 — Do not modify production configuration casually

Before changing:

```text
/etc/
application.conf
server.properties
nginx.conf
```

understand:

```text
What changes?
Why?
Who approved it?
How can it be rolled back?
```


---

## Rule 6 — Be careful with logs

```text

Request data
Internal IPs
Tokens
Identifiers
Business information
```

Follow company security and retention policies.

---

## Rule 7 — Do not blindly delete logs

Deleting a log may:

```text
Break troubleshooting
Destroy incident evidence
Interfere with log rotation
Violate retention requirements
```

```text
Application Configuration

Application Logs
        ↓
Error Evidence
        ↓
Incident Investigation
        ↓
Root Cause Analysis
```

```text
User reports payment failure
        ↓
Find application log
        ↓
grep "ERROR"
        ↓
Find database timeout
        ↓
Check related logs
        ↓
Identify issue
        ↓
Document evidence
        ↓
Resolve / Escalate
```

```bash
ls
cd
cp
mv
rm
cat
less
head
tail
grep
find
du
df
tar
```

These commands will become part of your **daily Application Support toolkit**.
