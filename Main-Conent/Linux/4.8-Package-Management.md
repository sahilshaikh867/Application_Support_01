# 1. Introduction

In Linux, applications are usually installed using **packages**.

For example, suppose an Application Support Engineer needs to troubleshoot a server and wants to use:

- `curl`
- `vim`
- `tree`
- `htop`
- `wget`
- `net-tools`

Instead of manually downloading and copying every required file, Linux provides **package management systems**.

Package management makes it easier to:

- install software
- remove software
- update software
- search software
- manage dependencies
- check installed versions
- track package changes
- maintain server consistency

Package management is an important skill for Linux administrators, DevOps engineers, Cloud Engineers, SREs and Application Support Engineers.

---

# 2. What is a Package?

A **package** is a collection of files required to install a particular software/application on a Linux system.

A package may contain:

```text
Application binaries
Configuration files
Libraries
Documentation
Metadata
Dependencies information
```

For example:

```text
curl package
│
├── curl executable
├── configuration information
├── documentation
└── dependency information
```

A package is normally distributed in a package format.

Common formats include:

| Linux Family | Package Format |
|---|---|
| Debian / Ubuntu | `.deb` |
| RHEL / CentOS / Fedora | `.rpm` |
| Amazon Linux | `.rpm` |

Example:

```text
curl_7.xx.x_amd64.deb
```

or:

```text
curl-8.xx.x.x86_64.rpm
```

---

# 3. What is Package Management?

**Package Management** is the process of installing, updating, removing and maintaining software packages on a Linux system.

Instead of manually managing software files, we use package managers.

Example:

```bash
sudo apt install curl
```

The package manager will:

1. Find the package
2. Download it
3. Check dependencies
4. Install required files
5. Configure the package
6. Complete the installation

---

# 4. Why Do We Need Package Management?

Without package management, installing software could become complicated.

Suppose an application requires:

```text
Application
   ↓
Library A
   ↓
Library B
   ↓
Library C
```

Manually installing everything would be difficult.

A package manager can automatically handle many of these dependencies.

### Major benefits

- Easy installation
- Easy removal
- Dependency management
- Version management
- Security updates
- Repository management
- Package verification
- Installation history
- Consistent server configuration

# 9. Package Lifecycle

A typical package lifecycle looks like this:

```text
Search
  ↓
Select
  ↓
Install
  ↓
Configure
  ↓
Use
  ↓
Update
  ↓
Upgrade
  ↓
Remove
```

Example:

```bash
apt search nginx
```

↓

```bash
sudo apt install nginx
```

↓

Use nginx.

↓

```bash
sudo apt update
sudo apt upgrade
```

↓

Later:

```bash
sudo apt remove nginx
```

# 10. APT Package Management

APT stands for:

> **Advanced Package Tool**

APT is commonly used on:

```text
Ubuntu
Debian
Linux Mint
```

---

## 10.1 Update Package Information

```bash
sudo apt update
```

Important:

```text
apt update
```

does **not** normally upgrade installed packages.

It refreshes the local information about packages available from repositories.

Think:

```text
Repository
     ↓
Refresh package information
     ↓
Local package metadata
```

---

## 10.2 Upgrade Installed Packages

```bash
sudo apt upgrade
```

This upgrades installed packages where applicable.

Typical flow:

```bash
sudo apt update
sudo apt upgrade
```

---

## 10.3 Install a Package

Example:

```bash
sudo apt install curl
```

Another example:

```bash
sudo apt install tree
```

---

## 10.4 Install Multiple Packages

```bash
sudo apt install curl wget vim
```

---

## 10.5 Remove a Package

```bash
sudo apt remove curl
```

This removes the package but may leave some configuration files depending on the package and situation.

---

## 10.6 Purge a Package

```bash
sudo apt purge package-name
```

Example:

```bash
sudo apt purge nginx
```

`purge` is generally used when you also want package configuration files removed.

---

## 10.7 Remove Unused Dependencies

```bash
sudo apt autoremove
```

This can remove packages that are no longer required.

**Production warning:** always review what will be removed before confirming.

---

## 10.8 Search for a Package

```bash
apt search nginx
```

Example:

```bash
apt search curl
```

---

## 10.9 Show Package Information

```bash
apt show curl
```

This can show information such as:

- package name
- version
- architecture
- dependencies
- description
- repository information

---

## 10.10 List Installed Packages

```bash
apt list --installed
```

To search within installed packages:

```bash
apt list --installed | grep curl
```

---

## 10.11 Check Package Policy and Versions

```bash

```

This can help you understand:

- installed version
- candidate version
- repository source


---

## 11.2 Show Package Information


## 11.3 List Files Installed by a Package

```bash

```

This is very useful for Application Support.

Example:


---

## 11.4 Find Which Package Owns a File

```bash

```

Example:

```bash
dpkg -S /usr/bin/curl
```

This answers:

## 11.5 Install a Local `.deb` Package



# 15. APT vs DNF vs RPM vs DPKG

| Feature | Debian/Ubuntu | RHEL/Fedora Family |
|---|---|---|
| High-level manager | APT | DNF |
| Older high-level manager | apt-get | YUM |
| Low-level tool | DPKG | RPM |
| Package format | `.deb` | `.rpm` |
| Install | `apt install` | `dnf install` |
| Remove | `apt remove` | `dnf remove` |
| Search | `apt search` | `dnf search` |
| Update | `apt update` + `apt upgrade` | `dnf update` |
| Installed packages | `apt list --installed` | `dnf list installed` |
| Package history | Depends/tooling | `dnf history` |

# 16. Package Dependencies

A package may require other packages to work.

Example:

```text
Application
    │
    ├── Library A
    │
    ├── Library B
    │
    └── Library C
```

These are called **dependencies**.

For example:

```text
Application A
     ↓
requires Library B
     ↓
requires Library C
```

The package manager can often identify and install these dependencies automatically.

---

## Dependency Problem Example

You run:

```bash
sudo dpkg -i myapp.deb
```

and get a dependency-related error.

The package may require:

```text
libxyz
libabc
```

which are not installed.

On Debian/Ubuntu, a common repair approach is:

```bash
sudo apt install -f
```

Then verify the application again.

# 24. Package History

Package history is very useful when troubleshooting production issues.

Imagine:

```text
Application was working at 10:00 AM.

Package update happened at 10:15 AM.

Application failed at 10:20 AM.
```

On DNF systems:

```bash
sudo dnf history
```

```bash
sudo dnf history info <ID>
```

This can help identify changes.

On Debian/Ubuntu, package activity may also be recorded in:

```text
/var/log/apt/
```

and:

```text
/var/log/dpkg.log
```

For example:

```bash
ls -l /var/log/apt/
```

and:

```bash

```

# 26. Package Cache

Package managers may keep downloaded package files or metadata locally.

This can help with:

- faster installations
- package management operations
- troubleshooting

But package caches can also consume disk space.

For example, on Debian/Ubuntu:

```bash
sudo apt clean
```

and:

```bash
sudo apt autoclean
```

Use cleanup commands carefully on production systems.

---

# 27. Package Security

Package installation is also a security concern.

Do not randomly download packages from unknown websites.

Prefer:

```text
Official repositories
Approved internal repositories
Trusted vendor repositories
Organization-approved packages
```

Package systems can use cryptographic signatures and repository metadata to help verify package authenticity.

---

## Why Verification Matters

Suppose someone gives you:

```text
important-server-tool.deb
```

from an unknown website.

Installing it directly could introduce:

- malware
- vulnerable software
- unauthorized changes
- backdoors

Therefore:

> Never treat package installation as a simple download-and-install operation in production.

Check the installed version.

### Example


or:

```bash

```

```bash

```

---

## Version Pinning / Holding

Sometimes organizations intentionally prevent a package from being automatically upgraded.

This is useful when:

```text

```

# 29. Application Support Scenarios

Package management becomes especially important during production troubleshooting.

---

## Scenario 1: Command Not Found

Developer says:

> "The server says `curl: command not found`."

Check:

```bash
which curl
```

or:

```bash
command -v curl
```

Check whether package is installed.

Ubuntu/Debian:

```bash
dpkg -l | grep curl
```

RHEL-based:

```bash
rpm -qa | grep curl
```

If approved, install:

```bash
sudo apt install curl
```

or:

```bash
sudo dnf install curl
```

Verify:

```bash
curl --version
```

---

# Scenario 2: Missing Library

Application error:

```text
error while loading shared libraries:
libxyz.so: cannot open shared object file
```

Possible causes:

- required package is missing
- wrong package version
- library path issue
- incomplete installation

Application Support investigation:

```text
1. Identify missing library
2. Determine which package provides it
3. Check installed package
4. Install approved package
5. Restart application if required
6. Verify application
```

On RPM-based systems:

```bash
dnf provides '*/libxyz.so'
```

On Debian-based systems, package search tools can be used to identify the provider.

---

# Scenario 3: Package Installation Fails

You run:

```bash
sudo apt install package-name
```

and installation fails.

Possible causes:

```text
Repository unavailable
DNS problem
Network problem
Dependency conflict
Disk full
Package lock
Broken package state
Repository configuration issue
```

Do not immediately repeat the same command.

First inspect the error.

---

# Scenario 4: Repository Unavailable

You may see errors such as:

```text
Could not resolve host
Failed to fetch
Repository unavailable
Connection timed out
```

Check network:

```bash
ping 8.8.8.8
```

Check DNS:

```bash
getent hosts google.com
```

Check connectivity:

```bash
curl -I https://example.com
```

Then inspect repository configuration.

---

# Scenario 5: Disk Full During Package Installation

Package installation may fail if the filesystem is full.

Check:

```bash
df -h
```

Check large directories:

```bash
du -sh /var/*
```

Package-related files often exist under:

```text
/var/cache/
```

and logs under:

```text
/var/log/
```

Do not delete files blindly.

Investigate first.

---

# Scenario 6: Package Update Causes Application Problem

Imagine:

```text
10:00 → Application healthy

10:30 → Package updated

10:35 → Application errors

10:40 → Users report issue
```

Application Support should investigate the timeline.

Check:

```text
Package history
Application logs
System logs
Configuration changes
Service status
Dependency versions
```

This is where change management and package management connect.

# 31. Troubleshooting Package Problems

## Problem 1: `apt: command not found`

Check OS:

```bash
cat /etc/os-release
```

You may be using an RPM-based distribution.

Try:

```bash
dnf --version
```

---

## Problem 2: `dnf: command not found`

Check:

```bash
cat /etc/os-release
```

Your system may use:

```bash
yum
```

Check:

```bash
yum --version
```

---

## Problem 3: Permission Denied

Example:

```text
Could not open lock file
Permission denied
```

Package management normally requires administrative privileges.

Try:

```bash
sudo apt install package-name
```

or:

```bash
sudo dnf install package-name
```

---

## Problem 4: Package Not Found

Example:

```text
Unable to locate package
```

Check:

```bash
sudo apt update
```

Then search again:

```bash
apt search package-name
```

Also verify:

- package name
- repository configuration
- network
- DNS
- distribution/version

---

# Problem 5: Dependency Error

Check the exact error.

For Debian-based systems:

```bash
sudo apt install -f
```

Then:

```bash
sudo apt update
```

For RPM-based systems, inspect dependency errors and repository/package availability before attempting repairs.

---

# Problem 6: Package Manager Lock

Sometimes another package operation is already running.

Check processes:

```bash
ps aux | grep -E 'apt|dpkg'
```

Do **not** immediately delete lock files.

First determine whether another legitimate package operation is running.

---

# Problem 7: Repository Connection Error

Check:

```bash
ping 8.8.8.8
```

DNS:

```bash
getent hosts google.com
```

HTTPS:

```bash
curl -I https://example.com
```

Then inspect repository configuration.

# 32. Production Safety Rules

Package management can change critical production systems.

Follow these rules.

### Rule 1 — Don't randomly install packages

Always understand:

```text
What?
Why?
From where?
Which version?
Who approved it?
```

---

### Rule 2 — Don't blindly run upgrade commands

Avoid running:

```bash
sudo apt upgrade
```

or:

```bash
sudo dnf update
```

on production servers without understanding the change and its impact.

---

### Rule 3 — Check dependencies

Before removing or upgrading packages, understand application dependencies.

---

### Rule 4 — Check disk space

Before large package operations:

```bash
df -h
```

---

### Rule 5 — Check package history

If an application suddenly breaks:

```text
Was a package recently updated?
```

---

### Rule 6 — Follow Change Management

Production package changes should generally follow the organization's:

```text
Change Request
    ↓
Impact Analysis
    ↓
Approval
    ↓
Maintenance Window
    ↓
Implementation
    ↓
Validation
    ↓
Documentation
```

---

### Rule 7 — Know whether a reboot is required

Some updates, especially kernel or low-level system components, may require a reboot or service restart.

Never reboot a production server simply because a package command suggested it without checking the change process.
